# lar-em-dia-app

Flutter app (web, Android and iOS) for **Lar em Dia**, a family budgeting and cash-flow projection app. It consumes the Rails API in [lar-em-dia-api](https://github.com/gabrieltrita/lar-em-dia-api).

## Stack

| Concern | Package |
|---|---|
| State management | `flutter_bloc` (Cubit for simple screens, Bloc for event-driven flows), `bloc_test` |
| Routing | `go_router` |
| HTTP | `dio` with `AuthInterceptor` (Bearer token, refresh on 401, single retry) |
| Immutable models and JSON | `freezed`, `json_serializable`, `build_runner` |
| Dependency injection | `get_it` + `injectable` |
| Secure storage | `flutter_secure_storage` (refresh token in Keychain / Keystore; access token in memory only) |
| Localization | `flutter_localizations` + `intl`, ARB files in `lib/l10n` (pt-BR) |
| Lint | `very_good_analysis` |
| Tests | `flutter_test`, `mocktail`, `bloc_test` |

Flutter 3.47.9 (Dart 3.13).

## Getting started

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:3000/api/v1
```

`API_BASE_URL` defaults to `http://localhost:3000/api/v1`. On the Android emulator the host machine is `10.0.2.2`, so use `--dart-define=API_BASE_URL=http://10.0.2.2:3000/api/v1`. The API must list the web origin in `CORS_ORIGINS`.

Generated files (`*.g.dart`, `*.freezed.dart`, `*.config.dart`, `lib/l10n/gen/`) are not committed: run `build_runner` after cloning and after changing annotated classes (`dart run build_runner watch -d` while developing). Localizations are generated by `flutter pub get` / `flutter gen-l10n`.

## API contract

- Successful responses are `{ "data": ..., "meta": ... }`; `ApiClient` returns them as `ApiResponse<T>`.
- Errors are `{ "error": { "code", "message", "details" } }`; `ApiClient` throws `ApiError`. Translate by `code` (and `details[field][].code`), never by `message`.
- Tokens: login and refresh return `data.tokens.access_token` and `data.tokens.refresh_token`. Mobile uses the body mode and keeps the refresh token in secure storage. The web build uses the API's cookie mode: every request sends `X-Token-Transport: cookie` and `withCredentials`, so the refresh token lives in an httpOnly cookie and never reaches JavaScript.
- DTOs use snake_case keys globally (`build.yaml` sets `field_rename: snake` for `json_serializable`).

## Balance, income, expenses and projection

| Route | Page |
|---|---|
| `/` | Home: latest balance, the projected balance at the end of this month, and this month's income (received and to receive) and expenses (paid and to pay), with shortcuts |
| `/balances` | Balance history; tap to edit, trash icon to delete after confirmation |
| `/balances/form` | Inform or edit a balance (`extra` carries the balance being edited); the amount may be negative and the date cannot be in the future |
| `/income?month=YYYY-MM` | Income of a month with its total; arrows move between months, swipe left deletes after confirmation |
| `/income/form` | New or edited income: category, description, amount, date and whether it was already received |
| `/expenses?month=YYYY-MM` | Expenses of a month with the total and the fixed and variable subtotals; the All / Fixed / Variable chips filter the list and the total |
| `/expenses/form` | New or edited expense: category, fixed or variable (preselected by the category's `default_nature`), description, amount, date and whether it was already paid |
| `/projection` | Projected balance at the end of each of the next 12 months: a line chart (`fl_chart`) and a list with income, expenses (fixed and variable) and the closing balance; negative months in red. Without a balance it asks for one first |

Income and expenses share the same pages and cubits: `EntriesPage` and `EntryFormPage` take the `EntryKind`, `MonthEntriesCubit` receives it as an injectable `@factoryParam` (`getIt<MonthEntriesCubit>(param1: kind)`), and the texts that differ use ICU `select` messages on the kind in `app_pt.arb`.

The projection comes from the API's `GET /projection` (`ProjectionRepository`); the app never recomputes balances. Chart values are converted to `double` only for drawing.

Amounts are integer cents end to end (`amount_cents` in the API, `int` in the app); `Money` formats and parses BRL text without `double`. A received income or paid expense is sent as `status: paid` with `paid_on` equal to its date. Category names come from the API in English and are shown in Portuguese by `key` (`categoryLabel`).

## Authentication

| Route | Page |
|---|---|
| `/login` | Email and password; moves to `/two-factor` when the account has 2FA, and offers a new confirmation link when the email is not confirmed |
| `/two-factor` | TOTP or backup code for the login challenge (only reachable from the login) |
| `/register` | Sign up with the terms and privacy consents, then `/check-email` |
| `/check-email` | Resend the confirmation link |
| `/confirm-email?token=` | Link from the confirmation email; confirms and signs in |
| `/forgot-password`, `/reset-password?token=` | Password recovery (the reset link comes by email) |

`SessionCubit` is the single source of truth for the session (`unknown`, `authenticated`, `unauthenticated`). It restores the session on start through `POST /auth/refresh`, and the router redirects on every change: unknown shows the splash, signed out users only reach the public pages, signed in users go home. When a refresh fails, `AuthInterceptor` clears the tokens and `SessionEvents` signs the user out.

The API email links point to the web routes above (`FRONTEND_URL` in the API). Deep links for the mobile apps come later.

## Demo build

`--dart-define=DEMO=true` builds an app that needs no API: both Dio clients get `DemoAdapter` (`lib/demo`) as their `HttpClientAdapter`, an in-memory fake of the Lar em Dia API in the spirit of Ember's Mirage. Everything above the adapter is the real app (repositories, DTOs, `AuthInterceptor`, refresh, error codes).

```bash
flutter run -d chrome --dart-define=DEMO=true
flutter build web --release --no-web-resources-cdn --dart-define=DEMO=true
```

- `DemoServer` answers login, refresh, logout, `/me`, categories, balances and entries (CRUD, filters, paging, the API's validation codes) and `GET /projection` with the API's rule. Email flows answer success without sending anything.
- `DemoSeed` creates the demo family relative to today: a balance on the first day of the month, a year of salary and fixed and variable expenses, the 13th salary in December and a trip that leaves one month negative. Entries due up to today are paid.
- The login page shows a demo notice with the account filled in (`DemoSeed.email` / `DemoSeed.password`). Data lives in memory, so reloading the page starts over.
- The demo uses hash URLs (`/#/projection`), so the web build opens from any address without server rewrites.
