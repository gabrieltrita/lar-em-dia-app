# lar-em-dia-app

Flutter app (web, Android and iOS) for **Lar em Dia**, a family budgeting and cash-flow projection app. It consumes the Rails API in [lar-em-dia-api](https://github.com/gabrieltrita/lar-em-dia-api).

## Stack

| Concern | Package |
|---|---|
| State management | `flutter_bloc` (Cubit for simple screens, Bloc for event-driven flows), `bloc_test` |
| Routing | `go_router` |
| HTTP | `dio` with `AuthInterceptor` (Bearer token, refresh on 401, single retry) |
| Immutable models and JSON | `freezed`, `json_serializable`, `build_runner` |
| Dependency injection | `get_it` + `injectable` |
| Secure storage | `flutter_secure_storage` (refresh token in Keychain / Keystore; access token in memory only) |
| Localization | `flutter_localizations` + `intl`, ARB files in `lib/l10n` (pt-BR) |
| Lint | `very_good_analysis` |
| Tests | `flutter_test`, `mocktail`, `bloc_test` |

Flutter 3.47.9 (Dart 3.13).

## Getting started

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:3000/api/v1
```

`API_BASE_URL` defaults to `http://localhost:3000/api/v1`. On the Android emulator the host machine is `10.0.2.2`, so use `--dart-define=API_BASE_URL=http://10.0.2.2:3000/api/v1`. The API must list the web origin in `CORS_ORIGINS`.

Generated files (`*.g.dart`, `*.freezed.dart`, `*.config.dart`, `lib/l10n/gen/`) are not committed: run `build_runner` after cloning and after changing annotated classes (`dart run build_runner watch -d` while developing). Localizations are generated by `flutter pub get` / `flutter gen-l10n`.

## Layout

```
lib/
  main.dart                   bootstrap: DI, then App
  app.dart                    MaterialApp.router, theme, localization
  core/
    config/env.dart           compile-time configuration (--dart-define)
    di/                       get_it + injectable (injection.dart, register_module.dart)
    network/                  ApiClient ({ data, meta } envelope), ApiError (error.code), AuthInterceptor
    routing/app_router.dart   go_router routes
    storage/token_storage.dart
    theme/app_theme.dart
  features/
    <feature>/
      data/                   DTOs, remote data sources, repository implementations
      domain/                 entities, repository contracts, use cases
      presentation/           pages, widgets, blocs/cubits
  l10n/app_pt.arb             user-facing copy (pt-BR)
test/                         mirrors lib/; helpers in test/helpers
tool/check_core_coverage.sh   fails below 100% line coverage in lib/core
```

## API contract

- Successful responses are `{ "data": ..., "meta": ... }`; `ApiClient` returns them as `ApiResponse<T>`.
- Errors are `{ "error": { "code", "message", "details" } }`; `ApiClient` throws `ApiError`. Translate by `code` (and `details[field][].code`), never by `message`.
- Tokens: login and refresh return `data.tokens.access_token` and `data.tokens.refresh_token`. Mobile uses the body mode. The web build will switch to the API's cookie mode (`X-Token-Transport: cookie`) when login lands in wave 1.
